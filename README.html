Getting started

Compare Caesar, OpenAI (Sol + web search), and Google Deep Research on the same 50 questions. Two judges choose one overall A/B winner, guided by New, Useful and Surprising. Rank the systems by their share of wins.

A complete run produces 150 answers and 600 judgments: every pair, both judges, both answer orders. The completed comparison includes all answers and explanations. For setup and methods, read the pipeline guide and research evaluation.

Install

Use Python 3.11–3.13 from the repository root. Caesar also needs the sibling Rome installation and its dependencies.

python -m pip install -e '.[test]'
python -m pip install -e ../rome
export OPENAI_API_KEY=...
export GOOGLE_API_KEY=...

GEMINI_API_KEY also works for Google. Credentials come from the environment; CREST does not automatically load dotenv files. Alternatively, set research.caesar.python_executable to the Python executable in an existing Rome environment.

Plan, generate, judge, analyze

Planning is local. Stage 1 and stage 2 make paid calls; stage 3 is local. Start with a one-question, three-answer pilot:

python -m crest plan --config crest/configs/crest.mbp.yaml --limit 1
python -m crest generate --config crest/configs/crest.mbp.yaml --limit 1

# Replace with stage 1's printed run_dir.
CREST_RUN=crest/results/YYYY-MM-DD/HH-MM-SS-TZ-ID
python -m crest judge --run "$CREST_RUN" --config crest/configs/crest.mbp.yaml
python -m crest analyze --run "$CREST_RUN" --config crest/configs/crest.mbp.yaml

Complete the pilot before starting the first full Caesar batch; omit --limit 1 for 50 questions. python -m crest run --config crest/configs/crest.mbp.yaml performs all three stages. The CLI also exposes plan, generate, judge, and analyze. Use --run PATH for an existing run; later stages otherwise select the latest generation run.

Models, budget, and concurrency

Caesar uses GPT-6.1 Sol with GPT-6 Luna exploration and knowledge-base helpers. OpenAI (Sol + web search) uses Sol high through the Responses API; Google Deep Research uses a managed agent whose internal models are provider-controlled. Judges are GPT-6 Astra high and Gemini 4 Argon high, without tools. See research settings and judge models.

$5 per answer is a target. Judging costs extra. Caesar reserves estimated request costs and synthesis time, with a configured two-hour worker timeout. Hosted research APIs expose no hard dollar cap, and Google’s estimates depend on assumed internal pricing. Saved records retain known costs, unresolved charges and timing.

The default profile starts at 6 concurrent research jobs and permits 24; judging starts at 8 and permits 32. The 64 GB jason-mbp profile starts research at 23 and permits 30; judging starts at 16 and permits 32. Limits rise after successful jobs and fall after rate-limit responses. Retries are bounded; uncertain submissions require reconciliation. See the provider limits and retry rules.

Results and reuse

Deep research comparison — 50 questions, 150 answers, and 600 judgments, with rankings, cost and time averages, and complete evidence.

crest/results/YYYY-MM-DD/HH-MM-SS-TZ-ID/
  run.json
  01-generate-YYYY-MM-DD_HH-MM-SS-TZ/    answers.jsonl, configurations.json, answers/
  02-judge-YYYY-MM-DD_HH-MM-SS-TZ/       judgments and frozen inputs/settings/rubric
  03-analysis-YYYY-MM-DD_HH-MM-SS-TZ/    ranking.json, ranking.csv, report.md
  .cache/judgments/
  .cache/analysis/

Directory dates use results_timezone: America/Chicago, with CDT or CST in place of TZ. Event timestamps remain UTC. Editable presets live in crest/configs/. Each answer’s configuration ID and full hash link to its frozen settings in configurations.json.

Answers are cached across runs in crest/results/.cache/generation/. Reruns create new timestamped stage folders while reusing matching cached work. answers.jsonl is canonical; analysis reads a precise stage-2 snapshot. Changing judges or rubric reuses answers. Existing generation runs keep their settings; start a new run for changed research settings, reusing unaffected shared-cache entries. Concurrency and retry changes preserve paid cache entries.

Records retain model, usage, cost and elapsed time, including provider queueing, polling and retries. Cache hits preserve original durations. Unavailable costs or durations remain unknown.

For intentional fresh calls, increment the relevant provider's revision; this is not a recovery procedure for an unresolved submission. Use python -m crest generate --run "$CREST_RUN" to recover existing generation work, then rerun stages 2 and 3.

Read the ranking

Rank by overall wins divided by comparisons on common complete questions. A full 50-question block gives each system 400 comparisons. Reports include ties, cycles, per-judge diagnostics, exclusions, and paired whole-question bootstrap intervals. There are no per-criterion rankings. These are the selected judges' preferences for the saved answers, not a validated general creativity measurement; see interpretation limits.

Development and history

After installing .[test], run the full test suite from the repository root:

python -m pytest

This runs both tests/ and crest_ais/tests/ in parallel, with one worker per logical CPU core. Use python -m pytest -n 0 for serial debugging, or python -m pytest -n 4 to choose the worker count.

Historical protocols, questions, papers, and results live under crest/_archive/ and remain separate from the current method. Old caches are not automatically imported.
