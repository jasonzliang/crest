# CREST Pipeline Implementation Plan

> **For agentic workers:** Use subagent-driven development. User explicitly requested parallel agents; implementation tasks own disjoint files. No worker may spawn agents or commit other workers' changes.

**Goal:** Replace Crest's coupled scoring harness with a simple cached generate → pairwise judge → rank pipeline.

**Architecture:** Atomic, locked job records separate expensive generation from judgments. Provider adapters checkpoint native background job IDs. Local analysis aggregates balanced complete-question blocks.

**Tech Stack:** Python 3.11+, httpx, PyYAML, pytest for development. Standard-library locking, hashing, reporting, and bootstrap statistics.

**Spec:** `docs/superpowers/specs/2026-10-25-pipeline-design.md`

## Global Constraints

- No paid calls, no .env/secrets reads, no unrelated edits, no new subagents from workers.
- Preserve original result/question/paper/research assets; archive old runtime.
- Use exact question text, complete answer content, strict A/B verdicts for each N/U/S criterion, both orders and two judges.
- Budget is per answer. Hosted research budget is explicitly a target, never advertised as a hard cap.
- Failed/incomplete responses never become successful cached answers. Persist remote IDs and ambiguous submissions.
- Follow the binding interfaces and defaults in the spec; report interface changes to the parent before making them.

## Decisions

- User requested edits in this exact checkout; work in place, which was clean, with disjoint ownership rather than creating a separate checkout.
- User requested parallel implementation; this overrides the workflow skill's default sequential implementer suggestion.
- User's later instruction adds stage three and explicitly authorizes modifying the Rome rubric. Preserve the original numeric rubric in Crest's historical archive before replacement.
- A fresh run consumes no API spend until a generation/judge command is explicitly invoked; implementation checks are offline.

## Final refinements

- Added standalone stage scripts, UTC timestamped folders, per-run judging/analysis caches, and immutable stage snapshots.
- Added adaptive concurrency, header-aware cooldowns and safe four-attempt retry defaults.
- Added source-sensitive Caesar cache keys, actual SDK-boundary cost auditing, synthesis reserve, and interrupted worker recovery.
- Independent provider and pipeline reviews drove regression fixes for accepted-request parsing failures, ambiguous submissions, expired background jobs, failed-job cost visibility, and recovery across source changes.
- Verification uses mock transports and offline installed Rome/SDK boundaries; no paid benchmark was launched.
