Paper comparison method

This pipeline compares released papers from ScientistOne, ScientistTwo, Sakana AI Scientist (v1), and Sakana Agentic Scientist (v3). Each judge chooses one overall creativity winner from a pair of papers, considering New, Useful, and Surprising together. The rubric and response format match current CREST.

The target is the released collection. Results describe the papers the judges preferred. They are not a controlled test on identical tasks or a prediction of future work.

The correction for unequal collection sizes

  1. Freeze eligible paper lists and hashes. Keep outputs explicitly labeled as human–AI co-discovery outside the primary pool.
  2. For each of six scientist matchups, sample paper pairs uniformly without replacement from all possible pairs. The default selects ten pairs per matchup. Each paper has the same chance of appearing within its own collection.
  3. Use two judges and both A/B orders. Each response contains one comparative reason and one overall winner.
  4. Average the overall choices within each matchup, then give a scientist’s three opponent matchups equal weight. Do not count or average separate N/U/S winners.

A larger collection gets no automatic score advantage. Equal numbers of sampled pairs control cost; equal opponent weights prevent large collections from dominating. A matchup with fewer possible pairs uses them all and retains the same opponent weight.

For example, win percentages of 40%, 60%, and 80% against the three opponents give a 60% overall score. This is a preference score for these papers, not an absolute creativity grade.

The default schedule is 60 paper pairs, 240 judge calls, and 240 overall binary choices, provided each matchup has at least ten possible pairs. These are not 240 independent scientific outputs; unique-paper coverage and repeated appearances are reported separately.

How N/U/S guides the decision

The three qualities guide one joint judgment. They do not receive separate winners or fixed numerical weights. See Overall creativity judgment for the literature and limits of this choice.

  • New: how clearly can the judge connect the paper’s least familiar contribution to earlier research? A weaker connection can suggest novelty, but the judge’s memory cannot verify it. Older papers may be easier to recognize.
  • Useful: does the paper explain how its approach works and provide evidence for its claimed benefit? Reading is not replication.
  • Surprising: how far does the paper’s central approach depart from the obvious approach to its question?

Papers can address different questions. Topics, publication dates, underlying AI models, computing resources, and which papers each team chose to release still differ; weighting cannot remove those differences.

What the intervals cover

Only a sample of possible paper pairs is judged. The ranges describe how sampling affects scores across all eligible pairs, for the saved papers, judges, prompts, and paper orders. A small sample can produce very wide ranges.

We increased the current sample after seeing the first results. The displayed calculation assumes a sample size chosen in advance, so these ranges are exploratory and do not carry a 95% confidence guarantee for the extended run. The run records when and how the sample was extended.

The calculation treats the response to each possible pair as fixed. Reusing a paper in different pairs is allowed because pairs are sampled. The ranges do not cover variation between repeated model calls, changes in the provider’s model, agreement with human experts, or future papers. More comparisons involving Sakana Agentic Scientist (v3)’s two papers do not create more independent papers from that system.

The design follows finite-population sampling; the bounded-interval approach follows sampling-without-replacement concentration bounds.

Inspect the evidence

  • Original PDFs, sources, checksums, duplicate records, and access limits are saved under crest_ais/data/.
  • Extracted text has page markers. Identifiable provenance headers are masked, while full text and an audit remain available. Plot images are not visually judged; content can still reveal provenance.
  • Runs retain exact inputs, rubric, seed, settings, judgments, usage, and errors. Paper text is data, never an instruction to the judge.
  • Missing judgments become neither losses nor zeroes. Primary ranks are withheld until the planned comparison is complete.
  • Charts come from saved results. Verbatim judge reasons are assessments that can be checked against the linked papers.

Code and verification

Code, tests, configuration, and run records live in crest_ais/. The pipeline validates the collection, freezes a plan, judges it, then analyzes and renders locally. Its protocol is versioned separately so changes to CREST do not alter an existing comparison.

Provider adapters preserve remote job IDs, raw responses, and safe resume behavior. The spend guard prevents new submissions after observed costs reach its target; in-flight calls can still incur charges. Credentials come from the environment.

Tests cover label reversal, unequal-count normalization, incomplete blocks, duplicate/invalid results, finite-pool sampling, content-sensitive caches, safe resume, PDF integrity, path checks, and HTML escaping.

Run the pipeline

Run these commands from the repository root. Planning and reporting are local; judging makes paid provider calls using credentials already in the environment.

python3 -m pip install -e '.[ais,test]'
python3 -m crest_ais plan
python3 -m crest_ais judge --workers-per-judge 16
python3 -m crest_ais report

To resume a specific experiment, pass --run-dir with its existing result directory. Creating another plan creates a new experiment. The worker override changes scheduling only; it leaves frozen prompts and model settings unchanged. The spend guard applies to observed current-run costs, with in-flight and unknown charges recorded separately.
