Getting started

Compare Caesar, OpenAI research, and Gemini Deep Research on the same 50 questions. Generate answers once, make one overall A/B creativity choice per judgment, and analyze balanced win rates with uncertainty. New, Useful, and Surprising guide each choice; they are not separate votes or weighted scores.

The full design plans 150 answers and 600 judgments: every pair, both judges, both answer orders. Current runs may be incomplete; coverage and exclusions accompany any reported ranking. Read the Research pipeline and Research evaluation.

Install

Use Python 3.11–3.13 from the repository root. Caesar also needs the sibling Rome installation and its dependencies.

python -m pip install -e '.[test]'
python -m pip install -e ../rome
export OPENAI_API_KEY=...
export GOOGLE_API_KEY=...

GEMINI_API_KEY also works for Google. Credentials come from the environment; CREST does not automatically load dotenv files. Alternatively, set research.caesar.python_executable to the Python executable in an existing Rome environment.

Plan, generate, judge, analyze

Planning is local. Stage 1 and stage 2 make paid calls; stage 3 is local. Start with a one-question, three-answer pilot:

python -m crest plan --config crest.mbp.yaml --limit 1
python stage1_generate.py --config crest.mbp.yaml --limit 1

# Replace with stage 1's printed run_dir.
CREST_RUN=results/YYYY-MM-DD/UTC-TIMESTAMP-UNIQUE-ID
python stage2_judge.py "$CREST_RUN" --config crest.mbp.yaml
python stage3_analyze.py "$CREST_RUN" --config crest.mbp.yaml

Complete the pilot before starting the first full Caesar batch; omit --limit 1 for 50 questions. python -m crest run --config crest.mbp.yaml performs all three stages. The CLI also exposes plan, generate, judge, and analyze. Use --run PATH for an existing run; later stages otherwise select the latest generation run.

Models, budget, and concurrency

Caesar uses GPT-6.1 Sol with GPT-6 Luna exploration/knowledge-base helpers, mini-like exploration, and budget- and time-aware synthesis. Native OpenAI research uses Sol high with web search; Google uses managed standard Deep Research. Judges are GPT-6 Astra high and Gemini 4 Argon high, without tools, with 32,768 output tokens each. See research settings and Judge models.

$5 per answer is a target, not a guaranteed spending cap. The 150-answer generation target is $750; judging is additional. Caesar reserves estimated request costs against its $5 SDK/handler guard and keeps $3 for synthesis and merging, with a 7,200-second per-answer limit and 600-second per-call timeout. Native provider APIs expose no hard dollar cap; Gemini research uses conservative cost estimates rather than final invoices. Reports retain estimated costs, failed paid attempts, and unknown bills.

crest.yaml starts research at 6 jobs and permits up to 24; judging starts at 8 and permits 32. The 64 GB jason-mbp profile starts research at 13 and permits 20 (Caesar 10→10, OpenAI 2→6, Gemini 1→4); judging starts at 4 and permits 16. Adaptive limits increase after successes and reduce on 429s, respecting cooldown headers. These are per-process limits, not account-wide guarantees. Native request retries allow four attempts, with creation retried only after an explicit 429 rejection. Caesar also permits bounded SDK retries for server 5xx errors while retaining uncertain-attempt cost reservations. Ambiguous native job creation requires reconciliation rather than blind resubmission.

Results and reuse

results/YYYY-MM-DD/UTC-TIMESTAMP-ID/
  run.json
  01-generate-UTC-TIMESTAMP/   answers.jsonl and readable answers/
  02-judge-UTC-TIMESTAMP/      judgments and frozen inputs/rubric/settings
  03-analysis-UTC-TIMESTAMP/   ranking.json, ranking.csv, report.md
  .cache/judgments/
  .cache/analysis/

Answers are cached across runs in results/.cache/generation/. Reruns create new timestamped stage folders while reusing matching cached work. answers.jsonl is canonical; analysis reads a precise stage-2 snapshot. Changing judges or rubric reuses answers. Existing generation runs keep their settings; start a new run for changed research settings, reusing unaffected shared-cache entries. Concurrency and retry changes preserve paid cache entries.

Alongside model, usage, and cost, each canonical answer/judgment row stores timing: UTC ISO start/completion, duration in seconds, source, and definition. Client elapsed time includes provider queueing, polling, retries, and interruptions; it excludes local scheduling before execution. Cache hits retain original durations; older checkpoints are backfilled when possible, otherwise timestamps/duration remain null.

For intentional fresh calls, increment the relevant provider's revision; this is not a recovery procedure for an unresolved submission. Use python stage1_generate.py --run "$CREST_RUN" to recover existing generation work, then rerun stages 2 and 3.

Read the ranking

Rank by overall wins divided by comparisons on common complete questions. A full 50-question block gives each system 400 comparisons. Reports include ties, cycles, per-judge diagnostics, exclusions, and paired whole-question bootstrap intervals. There are no per-criterion rankings. These are the selected judges' preferences for the saved answers, not a validated general creativity measurement; see interpretation limits.

Development and history

Run python -m pytest for the test suite. Historical protocols, questions, papers, and results live under crest/_archive/ and remain separate from the current method. Old caches are not automatically imported.
