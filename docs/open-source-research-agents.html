Open-source research agents built for creative answers

This page ranks five deep research agents from GitHub. Each has a mechanism for new or surprising answers, writes a cited report from any question, and runs with an OpenAI API key and no other paid service. They are candidates for the CREST research comparison alongside Caesar.

Checked 1 November 2026 from repository code, release pages, benchmark leaderboards and papers. Nothing was run; the evidence is what others have measured. Star counts are from the GitHub API on that date; GitHub dates are UTC.

How the five were chosen

We screened about a hundred repositories and read the code of the thirty that came closest. Three tests had to pass. The code must contain a step that pushes toward different or unexpected material, not only toward coverage or accuracy. The system must take any question and return a written, cited answer. It must run with OPENAI_API_KEY alone, using a free search path such as DuckDuckGo, OpenAI's own hosted search, or no search. Within that set, independent benchmark evidence and recent maintenance set the order.

Most popular deep research agents fail the first test. DeerFlow, local-deep-research, MiroFlow, Tongyi DeepResearch and the Alibaba WebWeaver pipeline improve coverage or rigor and have no divergent step. The creative mechanisms live mostly in the co-scientist re-implementations and the idea generators, and most of those fail the second or third test.

1. Co-STORM

stanford-oval/storm · 31,767 stars · MIT · last commit 30 Sep 2025 · pip install knowledge-storm

What only it does. A moderator agent watches the retrieved material and asks the one question that would bring in relevant evidence nobody has used yet. That is a built-in rule for surprise, not a hope that it happens.

How it works

Several expert agents, some chosen to hold opposing views, discuss the topic in turns. Each turn searches the web and answers with citations. Between turns the moderator ranks snippets that were retrieved but never cited, favoring ones far from the queries asked so far, and turns the best one into a new direction. The transcript becomes a mind map and then a cited article.

Evidence

  • Human raters scored Co-STORM 3.90 out of 5 for serendipity against 2.70 for a search engine (Co-STORM paper, Table 4, ten raters). self-reported
  • An automatic judge scored Co-STORM reports 3.05 for novelty against 2.44 for a retrieval chatbot and 2.50 for STORM with question answering (Table 3). self-reported
  • STORM scored 78.3 on the AstaBench scholarly QA set, next to OpenAI Deep Research at 79.4 (AstaBench, Table 6). independent
  • Two later papers that re-ran STORM and Co-STORM for novelty disagree on which is higher, so treat the novelty scores as a range, not a fact. independent

Running it on an OpenAI key

Build the language models with LitellmModel and your OPENAI_API_KEY, and pick DuckDuckGoSearchRM as the retriever. No search key is needed. The example script takes a topic string.

Watch out

The repository has had no commits since September 2025. It writes Wikipedia-style articles, so it follows its own format rather than the format a question asks for. It takes a topic, not a question; CREST would pass the question as the topic.

2. open_deep_research

langchain-ai/open_deep_research · 12,680 stars · MIT · archived 10 Aug 2026, still runs · Python 3.10 or later

What only it does. Of the five, it has the most outside evidence. With GPT-5 it beat OpenAI's own Deep Research on two third-party benchmarks, and its submitted insight score on DeepResearch Bench is above OpenAI's.

How it works

A supervisor reads the question and decides how many researchers to launch and what each should cover. The researchers run in parallel, each searching the web and pausing after every step to reflect with a think_tool on what it has and what is missing. A compression step strips each researcher's notes to the findings, and one writer turns the combined notes into the report.

Evidence

  • DeepResearch Bench insight 47.34 with GPT-5, against 43.73 for OpenAI Deep Research on the same board (original Gemini-judged board). submitted, scored by the benchmark
  • LiveResearchBench average 73.7 against 62.9 for o3 Deep Research (arXiv v1, Table 1 average column; the later version drops the average). In Figure 6, o3 wins about 13% of analysis-depth comparisons against it. independent
  • Wiki Live Challenge writing win rate 53.62 against 31.08 for o3 Deep Research. With GPT-4.1 the same code drops to 20.67, so the backbone matters. independent

Running it on an OpenAI key

Set search_api: openai; the agent then uses OpenAI's hosted web search and needs no other key. Set allow_clarification: false, or it may stop to ask the user a question instead of answering.

Watch out

LangChain archived the repository in August 2026, so bugs will not be fixed. Reasoning effort is not exposed in the configuration and needs a one-line patch. A context overflow returns the error text in place of the report.

3. Virtual Lab

zou-group/virtual-lab · 764 stars · MIT · last commit 31 Dec 2025 · OpenAI models only

What only it does. It runs the same meeting several times at high temperature, then holds a cooler merge meeting that keeps the best parts of each. Disagreement between runs is the raw material, and a critic agent speaks in every round.

How it works

A principal investigator agent assembles a team of scientist agents for the agenda. The team meets for a fixed number of rounds; a Scientific Critic speaks each round and the chair summarizes at the end. The library runs one meeting at a time, and run_meeting defaults to temperature 0.2. The project's nanobody notebook runs several meetings in parallel at 0.8 and then one merge meeting at 0.2 that is told to combine the best components into one answer. There is no web search; everything comes from the models.

Evidence

  • The authors used it to design nanobody candidates that were then made and tested in a wet lab (repository and paper). self-reported
  • No benchmark score for open-ended report quality or novelty was found. independent
  • Structurally it is the closest open system to a draft, critique and merge loop, which is the shape of the Caesar synthesis stage.

Running it on an OpenAI key

The default model is an OpenAI model and the only credential is OPENAI_API_KEY. Any agenda text can be the question. The parallel-and-merge loop lives in nanobody_design/run_nanobody_design.ipynb, not in the package, so CREST would copy that loop into its wrapper.

Watch out

No web search means no fresh evidence and no citations; it answers from model knowledge. The critic is prompted toward simple and rigorous, which may hold back surprise.

4. GPT-Researcher

assafelovic/gpt-researcher · 30,420 stars · Apache-2.0 · v3.7.0 on 26 Sep 2026 · pip install gpt-researcher · Python 3.12 or later

What only it does. Its deep mode recurses: every search produces learnings and follow-up questions, which spawn the next level of searches. Breadth and depth are two dials you set, so the tree of exploration is explicit and controllable.

How it works

A planner writes research questions for the topic. In the standard mode each question is searched in parallel and the pages are summarized into a report with APA citations. In deep mode the summaries become learnings, each learning spawns follow-up questions, and the process repeats to the configured depth before one writer assembles the report. Costs and visited sources are available through the API.

Evidence

  • On DeepResearchGym it scored 81.5 for insight and 89 for citation precision (Table 2). The Deep Research Comparator paper re-ran it in deep mode, scored 90.4 for insight, and ranked it first in a human preference study of 176 queries, ahead of Perplexity Deep Research. Both papers come from the same group. independent
  • Google's TTD-DR paper found it lost to OpenAI Deep Research with 18.3% and 9.4% win rates on two long-form sets. independent
  • In a pairwise novelty tournament judged by people it scored an Elo of 988, below plain retrieval at 1021 (Chain-of-Ideas paper, Table 26). This is the one measurement here that directly tests novelty, and it is not in its favor. independent

Running it on an OpenAI key

Set RETRIEVER=duckduckgo and OPENAI_API_KEY; choose models with SMART_LLM=openai:<model> and the matching FAST_LLM and STRATEGIC_LLM variables. The Python API returns the report, the costs and the source list.

Watch out

The code decides which models accept a temperature from a fixed list of names, so a new model name may be sent a temperature it rejects; pass LLM_KWARGS to override. The novelty evidence above is a real caveat for a creativity benchmark.

5. TTD-DR in optillm

algorithmicsuperintelligence/optillm · 4,334 stars · Apache-2.0 · repo pushed 2 Nov 2026 UTC, plugin folder 15 Oct 2025 · OpenAI-compatible proxy

What only it does. It writes the answer before it searches. The first draft comes from the model alone; each pass then looks for what the draft gets wrong or leaves out, searches for exactly that, and rewrites. The draft is treated like a noisy image that is cleaned up step by step.

How it works

It is an open implementation of Google's "test-time diffusion" deep researcher, inside a repository that is still active. The plugin folder itself has not changed since October 2025. A plan and a rough draft are produced from the model's own knowledge. A gap analysis lists missing or doubtful claims, a search step fetches evidence for those gaps only, and a revision step rewrites the draft. The loop repeats a set number of times and ends with a report carrying numbered citations.

Evidence

  • Google's TTD-DR paper reports wins over OpenAI Deep Research of 69.1% and 74.5% on the same two long-form report sets, for Google's internal system, not this code. self-reported
  • An open TTD-DR-style agent from a different author (ThinkDepth) scored 53.88 insight on the original DeepResearch Bench board, above open_deep_research (47.34) and OpenAI Deep Research (43.73). submitted, scored by the benchmark
  • No third party has scored the optillm plugin itself. independent

Running it on an OpenAI key

Run optillm as a proxy and request model deep_research-<model>, or call its run() function with an OpenAI client. Search uses a local Chrome window driven by optillm's web search plugin, so no search key is needed, but Chrome must be installed.

Watch out

The code's own comments say the paper's step that evolves several draft variants and picks the fittest is "not yet implemented", so part of the creative mechanism is missing. Google has released no official code. Chrome-driven Google search can be blocked.

Near misses

  • Kaimen Co-Scientist has the most complete creative loop found: ideas are generated in a simulated debate, ranked in an Elo tournament, and evolved by combining, simplifying and analogy. It runs on OpenAI models, but its web search needs a Tavily or Brave key and it returns ranked hypotheses rather than one report.
  • IDEAgent puts the strongest pressure toward non-obvious ideas, with hard gates for soundness, non-obviousness and diversity against earlier ideas. It has no web access, takes a topic plus background papers, and returns a set of ideas rather than an answer.
  • DeerFlow has the most recent commits of any project in the census and runs on DuckDuckGo and any OpenAI model. Its deep research is now a checklist skill inside a general agent framework, with no step aimed at novelty.
  • Si et al. AI-Researcher is the only pipeline we found that is backed by a large human study of idea novelty. Its prompts are written for machine learning research proposals and it also requires an Anthropic key.

Reading the evidence

Three kinds of numbers appear above. Self-reported means the authors measured their own system. Submitted means the authors sent outputs to a benchmark whose maintainers scored them. Independent means a third party ran the system. DeepResearch Bench has two boards with different judges, and scores across them do not compare. No benchmark measures "surprising" directly; insight and novelty scores are the nearest stand-ins, and most come from a single language-model judge.
