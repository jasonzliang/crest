\section{CREST}
\label{sec:crest}

\paragraph{Construct.} An output is scored creative only if it is simultaneously
\textbf{New}, \textbf{Useful}, and \textbf{Surprising}, each rated $1$--$10$, and only if all three
clear a fixed threshold \citep{runco2012standard,boden2004creative}. New is judged against a \emph{dated list of already
known answers} shipped with each question (so ``new'' means new relative to what is known, not
merely unlike web text); Useful is judged on soundness, workability, and satisfaction of the
question's hard rules; Surprising is judged relative to an \emph{expert's expected answer}, as
expectation-violation conditioned on correctness. Scoring follows the Consensual Assessment
Technique \citep{amabile1982cat,amabile1996context}. Citation accuracy is \emph{not} part of the
creativity score---it is a separate grounding check (\S\ref{sec:grounding}).

\paragraph{Task types (the axis that carries the finding).} Five core categories, each grounded
in a mechanism from the creativity literature:
\begin{itemize}
  \item \textbf{C1 Constrained}---invent within strict rules (bounded/exploratory creativity,
    \citealp{boden2004creative}; \citealp{simonton2003constrained}).
  \item \textbf{C2 Counterfactual}---reason about a ``what-if'' world
    (\citealp{byrne2005rational}).
  \item \textbf{C3 Cross-Domain}---connect two distant fields (structure-mapping,
    \citealp{gentner1983structure,falkenhainer1989sme}).
  \item \textbf{C4 Meta-Creativity}---invent a method, not an answer.
  \item \textbf{C5 Open-Ended}---many valid answers (transformational/blind-variation,
    \citealp{boden2004creative,campbell1960blind}).
\end{itemize}
CREST ships \textbf{50 questions---ten per task type}---spread over six domains (biology/medicine,
materials/chemistry, economics/business, law/policy, engineering, arts/humanities; eight to nine
per domain), so ``task type'' is not confounded with one specific
question. We \textbf{pre-register} the per-task-type prediction (win on C2/C3, parity on C4, null
on C1/C5) \emph{before} running CREST and confirm on fresh, held-out questions.

\paragraph{What each question ships with.} (i) a dated list of known answers (New baseline);
(ii) any hard rules to check (Useful); (iii) an expert's expected answer (Surprising baseline);
and (iv) the pre-registered predicted direction. See the released \texttt{schema.json} and
datasheet.

\paragraph{Two-sided prompt design.} The prompt shown to an agent is deliberately \emph{short and
open}---median $\sim$110 words---posing the task and little else. All axis-isolation and
anti-contamination machinery (rubric anchors, the known-answers and expert baselines, canary
strings, pre/post-cutoff labels) lives \emph{judge-side} and is never shown to the agent. This
preserves creative headroom, avoids over-steering the agent toward a target answer, and still keeps
grading reproducible because every scoring input is fixed and versioned.

\paragraph{Judge.} A multi-vendor panel---Anthropic, OpenAI, and Google models plus an open-weight
fourth in the full protocol, each pinned to a \emph{dated model snapshot}---scores blind to agent
identity and order-randomized; a model never judges an entrant of its own family
(\emph{leave-one-family-out}) to defuse self-preference \citep{panickssery2024own}, and the panel
score is the \emph{median} across judges. We report inter-judge reliability (Krippendorff $\alpha$,
ICC; \citealp{hayes2007alpha,koo2016icc}) and, critically, agreement with human experts on all five
task types, with humans the \emph{primary} scorer on the two types (C1/C5) where the panel is least
reliable (\S\ref{sec:experiments}).

\paragraph{Contamination and fairness controls.} Frontier entrants run through their
\emph{provider-native web search}; the permanently reproducible core is an open-weight entrant run
against \emph{one shared, dated, hashed retrieval index}. Because \emph{New} is judged against
per-item \emph{dated known-answers}, fresher retrieval cannot by itself inflate novelty. We ship the
index as URLs $+$ timestamps $+$ SHA-256 hashes (a signed manifest), embed \emph{canary strings},
label every item \emph{pre/post training-cutoff}, and maintain a \emph{rolling set} of brand-new
questions to detect training-data contamination. Every agent receives a matched tool and compute
budget.
