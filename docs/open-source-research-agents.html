Open-source research agents

This page ranks five deep research agents from GitHub, from most to least relevant to CREST. Each has a mechanism for new or surprising answers, writes a report from any question, and runs with an OpenAI API key and no other paid service. Four of the five search the web and cite their sources; Virtual Lab has no web search. They are candidates for the CREST research comparison alongside Caesar.

Checked 1 and 2 November 2026 from repository code, release pages, benchmark leaderboards and papers. Nothing was run; the evidence is what others have measured. Star counts are from the GitHub API on 2 November 2026; GitHub dates are UTC.

How the five were chosen

We screened about a hundred repositories and read the code of the thirty that came closest. Three tests had to pass. The code must contain a step that pushes toward different or unexpected material, not only toward coverage or accuracy. The system must take any question and return a written, cited answer; Virtual Lab is the one exception, since it has no web search and so, by default, its answers carry no citations. It must run with OPENAI_API_KEY alone, using a search option that needs no extra key, such as DuckDuckGo, OpenAI's own hosted search, or no search.

The five are ranked by how much running each would tell CREST about creative research answers. That takes two things together: a step in the code that pushes toward surprising material, and a run that turns a CREST question into a cited answer without much extra code. An agent weak on either ranks lower, and independent evidence and maintenance break ties. Each section starts with the reason for its rank.

Most popular deep research agents fail the first test. DeerFlow, local-deep-research, MiroFlow, Tongyi DeepResearch and the Alibaba WebWeaver pipeline improve coverage or rigor and have no dedicated creative step; WebWeaver's prompts only ask for "divergent thinking" and "original thinking" in passing. The creative mechanisms live mostly in open re-implementations of Google's AI co-scientist and in idea generators, and most of those fail the second or third test.

Papers behind the five

  • Co-STORM: Into the Unknown Unknowns: Engaged Human Learning through Participation in Language Model Agent Conversations (arXiv 2408.15232). It extends STORM (arXiv 2402.14207).
  • GPT-Researcher: no paper.
  • open_deep_research: no paper. LangChain describes it in a blog post.
  • Virtual Lab: The Virtual Lab of AI agents designs new SARS-CoV-2 nanobodies (Nature, 2025).
  • TTD-DR: Deep Researcher with Test-Time Diffusion (arXiv 2507.16075, Google). The optillm plugin is an outside implementation of this paper.

Reading the evidence

Most results on this page carry one of three tags. Self-reported means the authors measured their own system. Submitted means the authors sent outputs to a benchmark whose maintainers scored them. Independent means a third party ran the system.

DeepResearch Bench is a benchmark of research tasks with a public leaderboard. A language model judges each agent's reports on several dimensions; the one quoted here, insight, scores the depth of analysis. It has two leaderboards with different judges, Gemini 2.5 Pro on the original one and GPT-5.5 on the newer default one, and scores from the two do not compare. This page quotes only the original. DeepResearch Bench II, on the same site, is a separate benchmark, and DeepResearchGym, quoted for GPT-Researcher, has its own insight score on a different scale. OpenAI Deep Research is OpenAI's hosted research agent; some papers call it o3 Deep Research. No benchmark measures surprise directly. Insight and novelty scores are the nearest stand-ins, and most come from a single language-model judge.

1. Co-STORM

stanford-oval/storm · 31,768 stars · MIT · last commit 30 Sep 2025 · pip install knowledge-storm

Why it ranks first. Its code has the most direct push toward surprise of the five, and it is the only one with a measured serendipity result. It needs a short wrapper, takes a topic rather than a question, and has had no commits since September 2025.

What only it does. A moderator agent ranks the passages the experts retrieved but never cited. It favors passages that are relevant to the discussion but unlike the search queries that found them and the passages already cited, and turns the top ones into the next question.

How it works

Two or three expert agents, each given a different perspective, discuss the topic in turns. When an expert answers, it searches the web and replies with citations. After three answers in a row (the code's default) the moderator steps in. It ranks the text snippets retrieved since it last spoke that no expert has cited. A snippet scores higher when it is relevant to the discussion but different in meaning from the search queries that found it and from what has already been cited. The moderator then turns the top-ranked snippets into one new question. Each turn is filed into a mind map as the talk goes on, and the mind map's nodes become the sections of a cited article.

Performance

  • Ten users rated Co-STORM 3.90 out of 5 for serendipity against 2.70 for Google search (Co-STORM paper, Table 4). self-reported
  • An automatic judge, the Prometheus 2 model, scored Co-STORM reports 3.05 out of 5 for novelty, against 2.44 for a retrieval chatbot and 2.50 for the paper's STORM + QA baseline (Table 3). self-reported
  • STORM, the earlier pipeline in the same repository that Co-STORM extends, scored 78.3 on the AstaBench scholarly QA set, against 79.4 for OpenAI Deep Research (AstaBench, Table 6). This set scores citations and coverage, not novelty. independent
  • Two later papers that re-ran STORM and Co-STORM for novelty disagree: OmniThink puts Co-STORM ahead and Beyond Outlining puts STORM ahead (Table 2 in each). independent

Running it on an OpenAI key

Build the language models with LitellmModel and your OPENAI_API_KEY, set ENCODER_API_TYPE=openai, and pick DuckDuckGoSearchRM as the retriever after installing duckduckgo_search, which the package does not install. No search key is needed. The example script asks for the topic and for the user's turns at the keyboard, so CREST would call the runner from a short wrapper instead.

Watch out

The repository has had no commits since September 2025. It writes Wikipedia-style articles, so it follows its own format rather than the format a question asks for. It takes a topic, not a question; CREST would pass the question as the topic.

2. GPT-Researcher

assafelovic/gpt-researcher · 30,426 stars · Apache-2.0 (package metadata says MIT) · v3.7.0 on 26 Sep 2026 · pip install gpt-researcher · Python 3.12 or later

Why it ranks second. It answers any question unattended with a cited report, it is actively maintained, and it has the most independent measurements of the five, including a human novelty test. Its tree of follow-up questions explores widely, but no step in it aims at surprise directly.

What only it does. Its deep mode builds a tree of searches. Each search returns short findings, which the code calls learnings, and follow-up questions; the follow-ups become the next level of searches. Two settings fix the tree's shape: breadth, the number of searches at the first level, and depth, the number of levels.

How it works

A planner writes research questions for the topic. In the standard mode each question is searched in parallel and the pages are summarized into a report with APA citations. In deep mode each search returns learnings and follow-up questions. The follow-ups from one search become the next, deeper round, where each branch runs half as many searches as the level above, but at least two. This repeats to the configured depth, and one writer then assembles the report.

Performance

  • On DeepResearchGym, judged by GPT-4.1-mini, it scored 81.5 for insight and 89 for citation precision using its own commercial search (Table 2). Perplexity Deep Research scored higher on insight, 89.3. independent
  • The Deep Research Comparator paper, from the same CMU group, re-ran it in deep mode. It scored 90.4 for insight and ranked first of three systems in a human preference study of 176 queries, ahead of Perplexity Deep Research. independent
  • Google's TTD-DR paper found it lost to OpenAI Deep Research, with win rates of 18.3% on LongForm Research and 9.4% on DeepConsult, two long-form report sets. independent
  • In a novelty tournament where research ideas were compared two at a time, ten human raters gave it an Elo rating of 988, below a plain retrieval-augmented (RAG) baseline at 1021 (Chain-of-Ideas paper, Table 26). Elo is the chess rating method: wins raise the score and losses lower it, so higher is better. Three language-model judges in the same table put it above that baseline. It is the only novelty test of GPT-Researcher found. independent

Running it on an OpenAI key

Set RETRIEVER=duckduckgo and OPENAI_API_KEY, and install the ddgs package, which pip install gpt-researcher leaves out; choose models with SMART_LLM=openai:<model> and the matching FAST_LLM and STRATEGIC_LLM variables. The Python API returns the report, the costs and the source list.

Watch out

The code decides which models accept a temperature from a fixed list of names, so a new model name may be sent a temperature it rejects; pass LLM_KWARGS to override.

3. open_deep_research

langchain-ai/open_deep_research · 12,681 stars · MIT · last commit 10 Aug 2026, archived 21 Aug 2026 · Python 3.10 or later

Why it ranks third. It has the strongest report-quality results against OpenAI Deep Research and runs on OpenAI's hosted search, so it is the best quality baseline. Its parallel split aims at coverage more than surprise, and the repository is archived.

What only it does. A supervisor decides for each question how many researchers to launch, up to five at once, and gives each its own sub-topic, so each angle is researched on its own before one writer combines them. It also has the strongest outside results of the five against OpenAI Deep Research: with GPT-5 it beat that system on two third-party benchmarks and on submitted DeepResearch Bench insight.

How it works

A supervisor reads the question and decides how many researchers to launch, at most five at once, and what each should cover. Its prompt favors a single researcher unless the question splits cleanly. The researchers run in parallel. Each searches the web and, after every step, uses a think_tool to note what it has found and what is still missing. A compression step then removes duplicate and off-topic material from each researcher's notes but keeps every relevant finding and source. One writer turns the combined notes into the report.

Performance

  • DeepResearch Bench insight 47.34 with GPT-5, against 43.73 for OpenAI Deep Research on the same leaderboard (the original, Gemini-judged one). submitted
  • On LiveResearchBench it averaged 73.7 against 62.9 for OpenAI Deep Research. In head-to-head comparisons of analysis depth, OpenAI Deep Research won only 13.3% of the time. It trails OpenAI Deep Research on coverage, 65.3 against 85.0. (Figures from arXiv v1, Table 1 and Figure 7; the latest version drops the average and renumbers the figure as Figure 6.) independent
  • On Wiki Live Challenge, where a Gemini judge compares each report with the human-written Wikipedia article, its writing win rate was 53.62%, against 31.08% for OpenAI Deep Research. With GPT-4.1 as the underlying model, the same code drops to 20.67%. This benchmark comes from the DeepResearch Bench authors and uses the same Gemini judge. independent

Running it on an OpenAI key

Set search_api: openai; the agent then uses OpenAI's hosted web search and needs no other key. Set allow_clarification: false, or it may stop to ask the user a question instead of answering. Every published score above used Tavily, a search service that needs its own key, so nobody has measured this OpenAI-only setup.

Watch out

LangChain archived the repository in August 2026, so bugs will not be fixed. Reasoning effort is not exposed in the configuration, so setting it means patching the shared model setup. GPT-5 models are missing from the code's table of context limits, so when a GPT-5 run overflows its context window, the report is replaced by the error message.

4. Virtual Lab

zou-group/virtual-lab · 764 stars · MIT · last commit 31 Dec 2025 · OpenAI models only

Why it ranks fourth. Its parallel-and-merge loop has the strongest built-in divergence after Co-STORM's moderator and is the closest of the five to Caesar's synthesis stage. But it has no general web search, so by default its answers carry no citations, and the loop lives in a notebook that CREST would have to copy.

What only it does. Its nanobody notebook runs the same meeting five times in parallel at a high temperature (0.8), so the five answers differ, then holds one merge meeting at a low temperature (0.2) that keeps the best parts of each. A critic agent speaks in every round. Of the five agents, it is the closest to a draft, critique and merge loop, the shape of Caesar's synthesis stage.

How it works

Each meeting gets an agenda, the task text it must answer. In a first meeting a principal investigator agent proposes a team of scientist agents for the agenda, and the user then defines that team in code. The team meets for a set number of rounds, and the principal investigator, as team lead, summarizes at the end. A Scientific Critic agent joins every one-on-one meeting automatically. It joins team meetings only when it is added to the team, and the project's own runs add it. The library runs one meeting at a time, and run_meeting defaults to temperature 0.2. Temperature sets how random the model's output is; higher values give more varied answers. The project's nanobody notebook runs five meetings in parallel at 0.8 and then one merge meeting at 0.2 that is told to combine the best components into one answer. There is no general web search; an optional PubMed Central tool, off by default, can pull biomedical papers.

Performance

  • The authors used it to design 92 nanobodies that were made and tested in a wet lab; two showed improved binding to the recent JN.1 or KP.3 variants (Nature paper). self-reported
  • In a blinded human ranking whose data is in the repository, answers from the scientist team ranked best across 30 agendas: mean rank 1.13, against 2.13 for a generic team and 2.73 for a single generic agent (lower is better). self-reported
  • No third-party score for open-ended report quality or novelty was found.

Running it on an OpenAI key

The default model is an OpenAI model and the only credential is OPENAI_API_KEY. Any agenda text can be the question. The parallel-and-merge loop lives in nanobody_design/run_nanobody_design.ipynb, not in the package, so CREST would copy that loop into its wrapper.

Watch out

Without general web search it has no fresh evidence and no citations beyond PubMed; it answers mostly from model knowledge. With the default of zero rounds the critic never speaks, so set num_rounds. The critic's prompt asks for simple, rigorous answers, which may discourage surprising ones.

5. TTD-DR in optillm

algorithmicsuperintelligence/optillm · 4,334 stars · Apache-2.0 · last push 2 Nov 2026 · plugin folder last changed 15 Oct 2025 · OpenAI-compatible proxy

Why it ranks fifth. Its draft-first loop produces a cited report, but the paper's self-evolution step is not implemented, nobody has scored the plugin, and its visible Chrome search can stall at a CAPTCHA during unattended runs.

What only it does. It writes the answer before it searches. The first draft comes from the model alone; each pass then looks for what the draft gets wrong or leaves out, searches for exactly that, and rewrites. The paper calls this test-time diffusion, after image models that start from noise and clean it up step by step.

How it works

It is an outside implementation of Google's TTD-DR paper (Test-Time Diffusion Deep Researcher). The rough draft comes first, from the model's own knowledge. A first search on a few sub-queries then collects sources for the citation list. In each pass, a gap analysis lists missing or doubtful claims, a search fetches evidence for those gaps only, and a revision step rewrites the draft. The loop runs up to five times by default and stops early once the draft looks complete or stops improving. It ends with a report carrying numbered citations.

Performance

  • Google's TTD-DR paper reports win rates against OpenAI Deep Research of 69.1% on LongForm Research and 74.5% on DeepConsult, the same two sets as in the GPT-Researcher section, judged by Gemini 1.5 Pro. These results are for Google's own system built on Gemini 2.5 Pro, not for this code. self-reported
  • An open TTD-DR-style agent from a different author (ThinkDepth) scored 53.88 insight on the original DeepResearch Bench leaderboard, above open_deep_research (47.34) and OpenAI Deep Research (43.73). submitted
  • No third party has scored the optillm plugin itself, and it is on neither DeepResearch Bench leaderboard.

Running it on an OpenAI key

Run optillm as a proxy and request model deep_research-<model>, or call its run() function with an OpenAI client. Search uses a local Chrome window driven by optillm's web search plugin, so no search key is needed, but Chrome must be installed.

Watch out

The paper has a self-evolution step: it samples several variants of each step's output, scores and revises them, and merges them. The code's own comments say this step is "not yet implemented", so part of the creative mechanism is missing. Google has released no official code. Search runs Google in a visible Chrome window, waits 4 to 32 seconds per query, and stops at a CAPTCHA until someone presses Enter, so unattended runs can stall.

Near misses

  • Kaimen Co-Scientist has the most complete creative loop found: ideas are generated in a simulated debate, ranked in an Elo tournament, and evolved by combining ideas, simplifying them and drawing analogies. It runs on OpenAI models, but it takes a research goal rather than a question, and without a Tavily or Brave key it searches only PubMed, arXiv and Europe PMC. Its output is a research overview built from ranked hypotheses.
  • IDEAgent puts the strongest pressure toward non-obvious ideas: each idea must pass checks for soundness, non-obviousness and diversity from earlier ideas. It has no web access, takes a topic plus background papers, and returns a set of ideas rather than an answer.
  • DeerFlow has the most recent commits of any project named on this page and runs on DuckDuckGo and any OpenAI model. Its deep research is now a checklist skill inside a general agent framework, with no step aimed at novelty.
  • Si et al. AI-Researcher is the only pipeline we found that is backed by a large human study of idea novelty. It returns research proposals rather than an answer to a question, and its prompts are written for NLP and language-model research. It defaults to Claude, though an OpenAI engine can be selected.
