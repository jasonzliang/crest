\section{Experiments}
\label{sec:experiments}

\paragraph{What was actually run.} One run: $50$ CREST challenges $\times$ $5$ entrants $=250$
records, all scored, under live provider-native web search, judged by the three-vendor full panel.
The entrants are \texttt{openai\_deepresearch}, \texttt{openai\_shallow},
\texttt{gemini\_deepresearch\_max}, \texttt{gemini\_shallow} and \texttt{claude\_shallow}.

\textbf{The exploration agent of \S\ref{sec:caesar} is not among them}, so this section contains
\emph{no} evidence about it. Earlier drafts of this section reported a setup that was never run.
There was \emph{no} Perplexity entrant and \emph{no} open-weight entrant; there is \emph{no} frozen
shared index; budgets were \emph{not} matched; the panel is \emph{not} human-validated; \emph{no}
component ablation was performed; and \emph{no} judge$\leftrightarrow$human agreement study exists.
Those claims are removed rather than marked \texttt{[PLACEHOLDER]}, because a
placeholder in a results section reads as ``pending'' when the correct description is ``not
attempted.''

\paragraph{Task type dominates entrant identity.} The field mean spans $3.68$ (C1) to $6.60$ (C2), a
$2.92$-point range, against $2.06$ points between the best and worst entrant. So CREST does separate
task types---but the ordering (C2 $>$ C3 $>$ C5 $>$ C4 $>$ C1) is nearly the same for every entrant,
which is a property of the \emph{items}, not a dissociation among agents.

\paragraph{One rank reversal, and it is weak.} \texttt{openai\_shallow} leads on cross-domain C3
($7.50$ vs $6.70$) while \texttt{openai\_deepresearch} leads overall and on C2, C4 and C5. That is a
real agent$\times$category interaction, but it is a single reversal between two entrants from the
same vendor separated by $0.06$ points overall, and judge severity exceeds the entire
between-entrant spread---so it cannot be distinguished from judge noise. The strong
``rank-reversal, no single creativity scalar'' framing of earlier drafts is withdrawn.

\paragraph{The mechanistic hypothesis is untested, and this run cannot test it.} The prediction of
\S\ref{sec:caesar}---exploration drives C3, refinement drives C2, neither moves C1/C5---requires
component ablations on an agent that was never entered. Nothing in this table bears on it. Note also
that the commercial entrants here differ along many dimensions at once (model, search budget,
managed research loop), so even a per-category difference between them would not isolate a
mechanism; only a within-agent ablation would.

\paragraph{Prior human pilot (motivation only, \emph{not} a CREST result).} A small prior human
pilot---$5$ questions, ${\sim}22$ votes per item---motivated this study, reported as (agent
votes)--(competitor votes): C1 $5$--$18$ (loses), C2 $18$--$5$ (wins), C3 $20$--$2$ (wins), C4
$13$--$9$ ($\approx$ even), C5 $7$--$15$ (loses). \textbf{We do not claim the finding on this
pilot}: the pattern was observed post hoc, $n$ is tiny, and the pilot's data are not in this
repository, so the numbers above are not independently checkable from the artifact. Notably, the
CREST run does \emph{not} reproduce that pattern for any commercial entrant---the field is ordered by
task difficulty rather than showing C2/C3 wins against C1/C5 losses.

\paragraph{Statistics: what is computed.} Per-item mixed-effects models with a challenge-level random
intercept, bootstrap confidence intervals, an agent$\times$category interaction test, and a two-part
(hurdle) model for the grounding-gated score. Withdrawn from earlier drafts because they are not
implemented: a \emph{rater} random effect (the models have a challenge intercept only), multiplicity
correction, output length as a covariate, and MDE/power curves. The registered TOST is not usable as
registered---it tests a category composite against a reference of $0$ with $\pm1$ bounds on a
$1$--$10$ scale, which no category can satisfy---so null categories are reported descriptively
rather than as equivalence results.

\paragraph{Reproducibility.} Items, harness, judge config, analysis code and the promoted
\texttt{result/leaderboard.json} are tracked. The $250$-record run directory is not:
\texttt{result/runs/} is gitignored, so per-record judge rows and transcripts are absent from the
repository and this table cannot be recomputed from a fresh clone. Because retrieval is live, a
re-run will not reproduce these numbers exactly in any case.
