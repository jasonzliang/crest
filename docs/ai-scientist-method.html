Paper comparison method

This pipeline compares released papers from ScientistOne, ScientistTwo, Sakana AI Scientist (v1), Sakana AI Scientist (v2), and Sakana Agentic Scientist (v3). Each judge chooses one overall creativity winner from a paper pair, guided jointly by New, Useful and Surprising.

The target is the released collection. Results describe the papers the judges preferred. They are not a controlled test on identical tasks or a prediction of future work.

How this matches CREST

Both pipelines use one overall A/B choice and balanced win rates. New plans use the same N/U/S rubric; completed comparisons retain their exact saved prompts.

Equal weight for unequal collection sizes

  1. Freeze eligible paper lists and hashes. Keep outputs explicitly labeled as human–AI co-discovery outside the primary pool.
  2. For each of ten scientist matchups, sample up to ten distinct paper pairs uniformly without replacement. Use every pair if fewer than ten exist. Each paper has the same selection probability as other papers in its collection.
  3. Use two judges and both A/B orders. Each response contains one comparative reason and one overall winner.
  4. Average the four A/B choices for each paper pair, then the pairs within each matchup. A scientist’s score is the mean of its four matchup win rates.

Each opponent contributes 25% of a scientist’s score, regardless of collection size or sampled pair count. The pair cap controls cost.

For example, matchup win rates of 40%, 60%, 60% and 80% give a 60% overall score.

The current five-system schedule has 96 paper pairs and 384 overall judgments. Nine matchups use ten pairs; v2 versus v3 uses all six possible pairs from their three and two eligible papers. These are not 384 independent scientific outputs; unique-paper coverage and repeated appearances are reported separately.

How N/U/S guides the decision

The three qualities guide one decision, without separate scores or fixed weights. See the rubric’s literature and limitations. No human or domain-expert validation of this panel has been performed.

For new plans, judges must explain both papers and acknowledge close comparisons. If no substantive preference is supportable, the judge says so and chooses A; consistent indifference across both orders splits votes evenly. The published comparison retains its exact saved rubric and calls.

  • New: what does the central contribution add to earlier work, including substantive relationships and combinations of familiar components? Relevant identifiable prior work is evidence; a judge’s failure to recognize a precedent is not proof of historical novelty. An obscure peripheral detail provides no automatic advantage. Older papers may be easier to recognize.
  • Useful: does the contribution work for its stated task and development stage, and does its evidence support its claims? Explicit fictional or counterfactual premises are accepted; claims of established scientific results still require support. Reading is not replication.
  • Surprising: how does the substantive central approach depart from the obvious approach to its question? Unsupported or incoherent surprise cannot alone establish stronger overall creative quality.

Papers can address different questions. Topics, publication dates, underlying AI models, computing resources, and which papers each team chose to release still differ; weighting cannot remove those differences.

What the intervals cover

The ranges describe sensitivity to which eligible paper pairs were sampled, holding the papers, judges, prompts and orders fixed. Small samples produce wide ranges.

The sample size and five-system cohort were chosen after observing earlier results. The ranges therefore serve as exploratory references, without a 95% coverage guarantee. Four-system and five-system scores average different opponents and are not directly comparable.

Paper pairs are the sampling units; a paper can appear in multiple pairs. The calculation holds each possible pair’s judge responses fixed. It excludes variation from repeated calls, model changes, human agreement and future papers. Reusing Sakana Agentic Scientist (v3)’s two papers does not add independent papers.

The calculation combines Serfling sampling-without-replacement bounds, a Bonferroni correction across matchups, and the possible win rates of unsampled pairs. Sampling all pairs removes pair-selection uncertainty, while other limitations remain.

Inspect the evidence

One v2 run used a manually downloaded and reduced pest-detection dataset. This setup assistance is disclosed; the generated manuscript remains included because the authors report no human edits to its scientific content. See the v2 setup description and manuscript-generation account.

  • Original PDFs, sources, checksums, duplicate records, and access limits are saved under crest_ais/data/.
  • Extracted text has page markers. Identifiable provenance headers are masked, while full text and an audit remain available. Plot images are not visually judged; content can still reveal provenance.
  • Runs retain exact inputs, rubric, seed, settings, judgments, usage, and errors. Paper text is data, never an instruction to the judge.
  • Missing judgments become neither losses nor zeroes. Primary ranks are withheld until the planned comparison is complete.
  • Charts come from saved results. Verbatim judge reasons are assessments that can be checked against the linked papers.

Code and verification

Code and run records live in crest_ais/. The pipeline validates the collection, freezes a plan, judges it, then analyzes and renders locally. Reporting uses the saved prompts, presentations and settings.

Provider adapters preserve remote job IDs, raw responses, and safe resume behavior. The spend guard prevents new submissions after observed costs reach its target; in-flight calls can still incur charges. Credentials come from the environment.

Tests cover label reversal, unequal-count normalization, incomplete blocks, duplicate/invalid results, finite-pool sampling, content-sensitive caches, safe resume, PDF integrity, path checks, and HTML escaping.

Choose the rubric file

The JSON rubric field resolves relative to the configuration file. In crest_ais/configs/config.json or a configuration in the same directory, the default is:

"rubric": "../prompts/rubric_v2.txt"

To select the alternative rubric wording, use:

"rubric": "../prompts/rubric_v1.txt"

The alternative matches CREST’s corresponding rubric. Both selections use the same presentation and explanation checks. To use different wording, create a new plan: saved plans retain their exact prompts. Prepared paper text can be reused; the changed prompt creates distinct judgment identities.

Run the pipeline

Run these commands from the repository root. Planning and reporting are local; judging makes paid provider calls using credentials already in the environment.

python3 -m pip install -e '.[ais,test]'
python3 -m crest_ais plan
python3 -m crest_ais judge --workers-per-judge 16 --max-spend-usd 150
python3 -m crest_ais report

To resume a specific experiment, pass --run-dir with its result directory. Planning creates a new experiment. The worker override changes concurrency without changing saved prompts or model settings. The spend guard uses observed current-run costs; in-flight and unknown charges are recorded separately.
